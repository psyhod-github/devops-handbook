# Глоссарий

Короткие определения терминов. В скобках указана глава, где термин разбирается подробно.

## DevOps

**DevOps**: подход к частым и безопасным изменениям системы: культура общей ответственности, автоматизация и обратная связь. (01)

**CI (Continuous Integration)**: каждое изменение кода автоматически собирается и проверяется тестами. (01, 11)

**CD (Continuous Delivery / Deployment)**: проверенное изменение автоматически доставляется в окружение; в варианте Deployment — без ручного подтверждения. (01)

**IaC (Infrastructure as Code)**: инфраструктура описана в файлах, хранится в Git и создаётся инструментом. (01, 06)

**Least privilege**: принцип минимальных прав — у каждого ровно те права, которые нужны для задачи. (01, 04)

**Blast radius**: масштаб ущерба при взломе или поломке одного компонента. (01)

## AWS: инфраструктура и сеть

**Region (регион)**: географическая область с группой дата-центров AWS, например `us-west-2`. Ресурсы одного региона не видны в другом. (02)

**Availability Zone, AZ**: физически изолированный дата-центр (или группа) внутри региона. (02)

**VPC (Virtual Private Cloud)**: изолированная виртуальная сеть в AWS. (02)

**CIDR**: запись диапазона IP-адресов: `10.0.0.0/16` — 65 536 адресов, `/32` — один адрес. (02)

**Subnet (подсеть)**: часть адресного пространства VPC в одной AZ. Публичная, если в её route table есть маршрут `0.0.0.0/0 → IGW`. (02)

**Internet Gateway, IGW**: шлюз между VPC и интернетом. (02)

**NAT Gateway**: даёт серверам приватной подсети исходящий доступ в интернет без входящего. Платный (~$32 в месяц). (02)

**Route Table**: таблица маршрутов подсети: куда отправлять трафик для каждого диапазона адресов. (02)

**Security Group**: stateful firewall на уровне сетевого интерфейса; только разрешающие правила. (02)

**Network ACL**: stateless firewall на уровне подсети; есть и разрешающие, и запрещающие правила. (02)

**EC2**: сервис виртуальных серверов (инстансов). (02, 03)

**AMI (Amazon Machine Image)**: шаблон диска с ОС, из которого создаётся инстанс. (03)

**Instance type**: размер инстанса (CPU, память), например `t3.micro`. (02)

**Key Pair**: пара SSH-ключей; публичный хранится в AWS и на сервере, приватный (`.pem`) — у вас. (02)

**EBS**: сетевой диск для EC2. Оплачивается, пока существует, даже если инстанс остановлен. (03)

**Elastic IP**: постоянный публичный IPv4-адрес. Платный, пока выделен, даже без инстанса. (02)

**IMDS (Instance Metadata Service)**: адрес `169.254.169.254`, по которому инстанс узнаёт о себе и получает ключи роли. **IMDSv2** требует токен. (05)

## AWS: доступ

**Root user**: владелец аккаунта с неограниченными правами. Только для редких операций, всегда с MFA. (00)

**MFA**: второй фактор входа (код из приложения или аппаратный ключ). (00, 04)

**IAM**: сервис управления доступом в AWS. (04)

**IAM User**: человек или программа с постоянными учётными данными. (04)

**IAM Group**: набор пользователей; права группы получают все участники. (04)

**Policy**: JSON-документ с правилами `Effect` + `Action` + `Resource` (+ `Condition`). Бывают AWS managed, customer managed и inline. (04)

**ARN**: уникальное имя ресурса AWS: `arn:aws:сервис:регион:аккаунт:ресурс`. (04)

**Implicit deny / explicit deny**: запрет по умолчанию (нет Allow) и явный запрет (`Effect: Deny`), который сильнее любого Allow. (04)

**Access key**: пара «ID + секрет» для вызова API AWS. Постоянные начинаются с `AKIA`, временные — с `ASIA`. (03, 05)

**Profile (профиль CLI)**: локальная именованная настройка ключей и региона в `~/.aws/`. Не объект AWS. (03, 04)

**IAM Role**: набор прав без постоянных ключей, который временно принимают сервисы, люди или CI. (05)

**Trust policy**: политика роли, определяющая, **кто** может её принять. (05)

**Instance profile**: контейнер, через который роль прикрепляется к EC2-инстансу. (05)

**STS**: сервис AWS, выдающий временные учётные данные. (05)

**IAM Identity Center**: сервис единого входа для людей с временными учётными данными (бывший AWS SSO). (04)

**CloudShell**: терминал в браузере внутри консоли AWS с правами вошедшего пользователя. (04)

**CloudTrail**: журнал всех вызовов API в аккаунте: кто, что, когда, откуда. (04, 05)

## Terraform

**Terraform**: инструмент IaC от HashiCorp; описывает желаемое состояние инфраструктуры на языке HCL. (06)

**OpenTofu**: открытый форк Terraform (лицензия MPL, Linux Foundation), совместимый по синтаксису. (06)

**HCL**: язык конфигурации Terraform: блоки `тип "метка" { аргумент = значение }`. (06)

**Декларативный подход**: описание результата («что должно быть»), а не последовательности шагов. (06)

**Идемпотентность**: повторное применение даёт тот же результат и не создаёт дубликатов. (06)

**Provider**: плагин, который переводит код Terraform в вызовы API платформы, например `hashicorp/aws`. (06)

**Resource**: объект, который Terraform создаёт, изменяет и удаляет. (06)

**Data source**: объект, который Terraform только читает, не управляя им. (06)

**Variable / Output / Locals**: входные параметры, выходные значения и вычисляемые значения внутри модуля. (06)

**State**: файл, где Terraform хранит связь кода с реальными ресурсами. Может содержать секреты. (06, 07)

**Lock-файл (`.terraform.lock.hcl`)**: фиксация точных версий и хешей провайдеров. Коммитится. Не путать с блокировкой state. (06)

**Plan**: вычисленная разница между кодом, state и реальностью: `+` создать, `~` изменить, `-/+` пересоздать, `-` удалить. (06)

**Drift**: расхождение реальной инфраструктуры с кодом из-за ручных изменений. (06)

**Backend**: место хранения state: локальный файл, S3, HCP Terraform и т.д. (07)

**Remote state**: state в общем хранилище, доступный команде и CI. (07)

**State lock (блокировка state)**: защита от одновременных `apply`. В S3 — объект `.tflock` (`use_lockfile = true`). (07)

**Module**: папка с `.tf` файлами, вызываемая с параметрами; корневой модуль — папка, где запускается Terraform. (07)

**`moved`**: блок, сообщающий Terraform о новом адресе ресурса без его пересоздания. (07)

**User Data**: скрипт, который инстанс выполняет при первой загрузке. (08)

**cloud-init**: стандартный инструмент первичной настройки облачных серверов; выполняет User Data. (08)

**`templatefile()`**: функция Terraform, подставляющая значения в файл-шаблон. (08)

**Immutable infrastructure (неизменяемая инфраструктура)**: серверы не меняют после создания, а заменяют новыми из кода. (08)

## Docker

**Image (образ)**: неизменяемый шаблон с приложением и всем, что нужно для его запуска: файлы, зависимости, команда запуска. Собирается из Dockerfile. (09)

**Container (контейнер)**: запущенный экземпляр образа, то есть изолированный процесс на хостовой машине. Из одного образа можно запустить сколько угодно контейнеров. (09)

**Dockerfile**: текстовый файл с инструкциями (`FROM`, `COPY`, `RUN`, `CMD`…), по которым `docker build` собирает образ. (09)

**Layer (слой)**: результат одной инструкции Dockerfile, которая меняет файлы (`RUN`, `COPY`, `ADD`). Слои кешируются и переиспользуются между сборками. (09)

**Build context**: набор файлов, который `docker build` отправляет движку для сборки. Обычно это текущая папка (`.`) за вычетом того, что указано в `.dockerignore`. (09)

**Base image (базовый образ)**: образ из инструкции `FROM`, на котором строится ваш. Например, `node:22-alpine`. (09)

**Tag (тег)**: метка версии образа после двоеточия: `backend:1.0`. Если тег не указан, используется `latest`. (09)

**Registry (реестр)**: хранилище образов, например Docker Hub, Amazon ECR, GitHub Container Registry. (09, 12)

**Port mapping (`-p`)**: проброс порта хоста в порт контейнера: `-p ХОСТ:КОНТЕЙНЕР`. (09)

**Alpine**: минималистичный дистрибутив Linux (~5 МБ). Часто используется как основа компактных образов. (09)

**Docker Compose**: инструмент для описания и запуска нескольких связанных контейнеров одним YAML-файлом. (10)

**Service (Compose)**: описание контейнера в `docker-compose.yml`; имя сервиса — DNS-имя в сети стека. (10)

**Bind mount**: монтирование файла или папки хоста в контейнер. (10)

**Named volume**: хранилище данных, которым управляет Docker; переживает удаление контейнера. (10)

**Healthcheck**: команда, которой Docker проверяет готовность контейнера. (10)

**Stateless / stateful**: сервис без собственного состояния (backend) и с ним (Redis, базы данных). (10)

## CI и Jenkins

**Jenkins**: CI-сервер с открытым кодом; выполняет pipeline, описанные в `Jenkinsfile`. (11)

**Controller**: главный сервер Jenkins: интерфейс, настройки, история, credentials. (11)

**Agent / executor**: машина и «слот», где выполняются шаги сборки. (11)

**Job / build**: задача в Jenkins и один её запуск с номером. (11)

**Pipeline / stage / step**: процесс сборки, его этапы и отдельные действия. (11)

**Jenkinsfile**: файл с описанием pipeline; хранится в репозитории. (11, 12)

**Declarative / scripted pipeline**: строгий синтаксис `pipeline { }` и свободный Groovy `node { }`. (11)

**Smoke test**: минимальная проверка «запускается и отвечает». (12)

**Registry (реестр)**: хранилище образов: Docker Hub, Amazon ECR, GHCR. (12)

**Credentials (Jenkins)**: зашифрованное хранилище секретов Jenkins; в pipeline — через `withCredentials`. (12)

**Poll SCM / webhook**: Jenkins сам опрашивает git / git-хостинг сообщает Jenkins о push. (12)

**Artifact (артефакт)**: результат сборки, который разворачивают: образ, пакет, бинарный файл. (12)

## Ansible

**Ansible**: инструмент управления конфигурацией: приводит серверы к описанному состоянию по SSH, без агентов. (13)

**Control node / managed node**: машина, где запускают Ansible, и серверы, которыми он управляет. (13)

**Inventory**: список серверов, разбитых на группы. Бывает статическим (`inventory.ini`) и динамическим (плагин `aws_ec2`). (13)

**Module**: готовое действие Ansible: `ansible.builtin.dnf`, `copy`, `service`. (13)

**FQCN**: полное имя модуля с коллекцией: `ansible.builtin.copy`. (13)

**Task / play / playbook**: вызов модуля; набор задач для группы серверов; YAML-файл с play. (13)

**Facts**: сведения о сервере, которые Ansible собирает в начале play. (13)

**become**: выполнение задач с повышенными правами (`sudo`). (13)

**Ad-hoc команда**: разовый вызов модуля без плейбука: `ansible web -m ping`. (13)

**Check mode (`--check`)**: пробный прогон без изменений, аналог `terraform plan`. (13)

**Role**: самостоятельный блок настройки со стандартной структурой папок. (14)

**Handler**: задача, выполняемая по уведомлению (`notify`) и только при изменениях. (14)

**Jinja2**: язык шаблонов: `{{ variable }}`, `{% if %}`. (14)

**Collection**: пакет с модулями и ролями, например `community.docker`. Версии фиксируются в `requirements.yml`. (14)

**Extra vars (`-e`)**: переменные из командной строки, имеют наивысший приоритет. (14)

**Rolling update**: обновление серверов партиями с проверкой после каждой. В Kubernetes — постепенная замена подов Deployment. (14, 15)

## Kubernetes

**Kubernetes (K8s)**: оркестратор контейнеров: поддерживает описанное состояние приложений на кластере машин. (15)

**Cluster / node**: набор машин под управлением Kubernetes и одна машина в нём. (15)

**Control plane**: управляющие компоненты: API server, etcd, scheduler, controller manager. (15)

**kubelet**: агент на каждой ноде, запускает контейнеры подов. (15)

**kubectl**: CLI для работы с API Kubernetes. (15)

**Manifest**: YAML-описание объекта Kubernetes (`apiVersion`, `kind`, `metadata`, `spec`). (15)

**Reconciliation loop (цикл согласования)**: контроллеры постоянно приводят фактическое состояние к желаемому. (15)

**Pod**: минимальная единица запуска: один или несколько контейнеров с общей сетью и IP. (15)

**Deployment / ReplicaSet**: Deployment управляет ReplicaSet-ами и обновлениями, ReplicaSet держит нужное число подов. (15)

**Labels / selector**: метки на объектах и фильтр по ним; так Deployment и Service находят поды. (15)

**Namespace**: логическое разделение ресурсов внутри кластера. (15)

**Readiness / liveness probe**: проверки «готов к трафику» и «жив ли процесс». (15)

**minikube**: локальный кластер Kubernetes на одной машине. (15)

**PersistentVolumeClaim (PVC)**: заявка на постоянное хранилище, переживающее под. (15)

**Service**: стабильный адрес и балансировка перед набором подов. Типы: ClusterIP, NodePort, LoadBalancer. (16)

**Endpoints / EndpointSlice**: список адресов готовых подов за Service. (16)

**Ingress / Ingress Controller**: правила HTTP-маршрутизации по хосту и пути и программа, которая их исполняет. (16)

**Gateway API**: следующее поколение API входящего трафика: `Gateway` + `HTTPRoute`. (16)

**ConfigMap / Secret**: конфигурация и чувствительные данные отдельно от манифеста Deployment. (17)

**ServiceAccount**: учётная запись пода для доступа к API Kubernetes. (17)

**RBAC (Role, RoleBinding, ClusterRole)**: права в Kubernetes: что разрешено и кому. (17)

**Requests / limits**: гарантированные и максимальные ресурсы контейнера. (18)

**Throttling / OOMKilled**: замедление при превышении лимита CPU / убийство контейнера при превышении лимита памяти. (18)

**metrics-server**: собирает потребление CPU и памяти подов для `kubectl top` и HPA. (18)

**HPA (HorizontalPodAutoscaler)**: автоматически меняет число реплик по метрикам. (18)
