# 00 · Подготовка: инструменты, AWS-аккаунт, защита от расходов

!!! abstract "В этой главе"
    **Что вы сделаете:** установите все инструменты пособия, заведёте аккаунт AWS, защитите его через MFA и настроите оповещение о расходах. После главы у вас будет готовое рабочее место, и дальше не придётся отвлекаться на установку.

    **Что нужно до начала:** компьютер на Windows 10/11, macOS или Linux, права администратора, банковская карта для регистрации в AWS.

    **Сколько времени:** 1–2 часа, большая часть уходит на скачивание.

## Зачем это нужно

DevOps-инженер работает в терминале и с облаком. Если готовить окружение по кусочкам «по ходу дела», каждая глава начнётся с получаса борьбы с установкой. Сделайте это один раз здесь.

Вторая причина важнее. **Облако берёт деньги за каждую минуту работы ресурсов.** Забытый сервер, утёкший ключ, случайно выбранный дорогой тип инстанса — и в конце месяца приходит счёт. Защиту от этого настраивают до того, как создан первый ресурс, а не после.

## Требования к компьютеру

| | Минимум | Рекомендуется |
|---|---|---|
| ОЗУ | 8 ГБ | 16 ГБ (Kubernetes в главах 15–18 требователен к памяти) |
| Свободное место | 20 ГБ | 40 ГБ |
| ОС | Windows 10 22H2 / 11, macOS 13+, Ubuntu 22.04+ | — |
| Процессор | 64-битный с поддержкой виртуализации | — |

На Windows виртуализация должна быть включена в BIOS/UEFI: без неё не запустится Docker Desktop. Проверить: Диспетчер задач → Производительность → ЦП → строка «Виртуализация: Включено».

### Установка

=== "Windows"

    Откройте **PowerShell** и выполните. `winget` встроен в Windows 10/11.

    ```powershell
    winget install --id Git.Git -e
    winget install --id Microsoft.VisualStudioCode -e
    winget install --id Amazon.AWSCLI -e
    winget install --id Hashicorp.Terraform -e
    winget install --id Docker.DockerDesktop -e
    winget install --id Kubernetes.kubectl -e
    winget install --id Kubernetes.minikube -e
    ```

    После установки **закройте и снова откройте терминал**, чтобы обновилась переменная `PATH`. Docker Desktop попросит перезагрузку и включит WSL 2.

    !!! warning "Ansible на Windows"
        Ansible не работает как управляющая машина на Windows. Поставьте **WSL 2 с Ubuntu**: `wsl --install -d Ubuntu`. Ansible вы установите внутри Ubuntu в главе 13. WSL 2 всё равно нужен Docker Desktop, так что лишней работы не будет.

=== "macOS"

    Нужен [Homebrew](https://brew.sh). Если его нет, команда установки есть на главной странице brew.sh.

    ```bash
    brew install git awscli kubectl minikube ansible
    brew tap hashicorp/tap
    brew install hashicorp/tap/terraform
    brew install --cask visual-studio-code docker
    ```

    Terraform ставится из официального tap HashiCorp: в основном репозитории Homebrew он заморожен на старой версии из-за смены лицензии.

    После установки запустите **Docker** из папки «Программы» и дождитесь иконки кита в строке меню.

=== "Linux (Ubuntu)"

    ```bash
    sudo apt update && sudo apt install -y git unzip curl

    # AWS CLI v2 (не ставьте awscli из apt — там может быть v1)
    curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip
    unzip awscliv2.zip && sudo ./aws/install && rm -rf aws awscliv2.zip
    ```

    Для остальных инструментов используйте официальные репозитории, команды там регулярно обновляются:

    - Terraform — [developer.hashicorp.com/terraform/install](https://developer.hashicorp.com/terraform/install) (вкладка Linux → Ubuntu/Debian);
    - Docker Engine — [docs.docker.com/engine/install/ubuntu](https://docs.docker.com/engine/install/ubuntu/), затем `sudo usermod -aG docker $USER` и перелогиньтесь;
    - kubectl — [kubernetes.io/docs/tasks/tools/install-kubectl-linux](https://kubernetes.io/docs/tasks/tools/install-kubectl-linux/);
    - minikube — [minikube.sigs.k8s.io/docs/start](https://minikube.sigs.k8s.io/docs/start/);
    - Ansible — `sudo apt install -y pipx && pipx install --include-deps ansible`.

!!! success "✅ Проверь себя"
    ```bash
    git --version          # → git version 2.4x.x
    aws --version          # → aws-cli/2.x.x ...   (именно 2, не 1)
    terraform -version     # → Terraform v1.1x.x  (не ниже 1.11)
    docker --version       # → Docker version 2x.x.x
    docker run hello-world # → Hello from Docker!
    kubectl version --client   # → Client Version: v1.3x.x
    minikube version       # → minikube version: v1.3x.x
    ```
    Команда не найдена? Перезапустите терминал. Не помогло — перезагрузите компьютер: установщик мог не обновить `PATH` в уже открытых окнах.

### Настроить Git

Один раз укажите имя и email. Они попадут в каждый коммит:

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```

!!! tip "Публичный email"
    Если репозитории будут публичными, вместо личного email используйте адрес вида `12345+username@users.noreply.github.com`. Его можно найти на GitHub в Settings → Emails. Так личный адрес не попадёт в историю коммитов.

### Скачать пособие

Сделайте fork репозитория на GitHub (кнопка **Fork**), затем клонируйте **свою** копию:

```bash
git clone https://github.com/<your-github-user>/devops-handbook.git
cd devops-handbook
```

В своём fork можно коммитить домашние задания, ничего не ломая в оригинале.

## Аккаунт AWS

### Как устроен Free Tier

При регистрации AWS предлагает выбрать план:

| | Free plan | Paid plan |
|---|---|---|
| Кредиты | $100 сразу + до $100 за изучение сервисов | Те же кредиты |
| Срок | 6 месяцев или пока не кончатся кредиты | Без ограничений |
| Что после | Аккаунт закрывается, денег не списывают | Оплата по факту использования |
| Сервисы | Только часть сервисов | Все сервисы |

Для пособия подходит **Free plan**: EC2 `t3.micro`, S3, IAM, VPC в нём есть, а случайно уйти в минус нельзя. Условия меняются, поэтому актуальные проверяйте на [aws.amazon.com/free](https://aws.amazon.com/free/).

!!! warning "Кредиты — это тоже деньги"
    Кредиты тратятся так же, как реальные деньги. Забытый NAT Gateway (~$32 в месяц) или EC2 крупного типа съедят их за пару недель, и аккаунт закроется раньше, чем вы дойдёте до Kubernetes. Правило уборки после каждой главы действует и на Free plan.

### Регистрация

1. Откройте [aws.amazon.com](https://aws.amazon.com) → **Create an AWS Account**.
2. Укажите email и имя аккаунта. Этот email станет логином **root user**, главного пользователя с неограниченными правами.
3. Подтвердите email, введите данные карты и телефон.
4. Выберите план (см. таблицу выше).

### Защитить root user

Root user может всё: удалить аккаунт, сменить карту, создать любые ресурсы. Если его пароль утечёт, вы потеряете контроль над аккаунтом. Поэтому:

1. Войдите как root → правый верхний угол, имя аккаунта → **Security credentials**.
2. **Multi-factor authentication (MFA)** → **Assign MFA device** → *Authenticator app*.
3. Отсканируйте QR-код приложением-аутентификатором (Google Authenticator, Microsoft Authenticator, 1Password и т.п.) и введите два кода подряд.
4. **Никогда не создавайте access keys для root.** Для работы из терминала в главах 03–04 вы создадите отдельного IAM-пользователя с ограниченными правами.

!!! success "✅ Проверь себя"
    Выйдите из консоли и войдите снова как root: после пароля AWS должен запросить код MFA.

### Выбрать регион

Регион — это географическое расположение дата-центров AWS (подробнее в главе 02). Во всём пособии используется **`us-west-2` (Oregon)**: он недорогой и поддерживает все нужные сервисы.

Выберите его в правом верхнем углу консоли. **Ресурсы в разных регионах не видны друг другу:** если «пропал» сервер, первым делом проверьте регион.

## Бюджет: оповещение о расходах

Настройте до того, как создадите первый ресурс. Это две минуты.

1. Консоль → поиск **Budgets** → **Billing and Cost Management → Budgets** → **Create budget**.
2. Выберите **Use a template** → **Monthly cost budget**.
3. *Budget name*: `monthly-10usd`, *Budgeted amount*: **10** USD.
4. *Email recipients*: ваш email → **Create budget**.

Шаблон создаёт оповещения при 85% и 100% фактических расходов, а также при прогнозе выше 100%.

!!! success "✅ Проверь себя"
    **Budgets** → бюджет `monthly-10usd` в списке, *Amount* = $10.00.

!!! info "Бюджет не останавливает расходы"
    AWS Budgets **только присылает письмо**. Ресурсы продолжат работать и тратить деньги, пока вы их не удалите. Данные о расходах обновляются с задержкой до нескольких часов, поэтому письмо может прийти не сразу. Бюджет — это сигнализация, а не предохранитель. Предохранитель — привычка удалять ресурсы.

Дополнительно можно создать шаблон **Zero spend budget**: он сообщит о первом же центе сверх бесплатных лимитов.

## Правила безопасности на всё пособие

Эти правила будут повторяться в каждой главе. Запомните их сейчас.

1. **Никогда не коммитьте секреты:** `*.pem`, `*.tfstate`, `.env`, `terraform.tfvars`, `inventory.ini`, файлы с access keys. В репозитории пособия они уже добавлены в `.gitignore`. Проверяйте `git status` перед каждым коммитом.
2. **Не храните ключи в заметках, мессенджерах и документах.** Место ключа — `~/.aws/credentials` на вашем компьютере (глава 03) и менеджер паролей.
3. **Утёк ключ — сразу отзывайте** в IAM → Users → Security credentials → Deactivate → Delete. Удаление строки из файла ключ не отзывает.
4. **Каждая сессия в AWS заканчивается уборкой:** `terraform destroy` или удаление ресурсов вручную. Это правило, а не опция.
5. **SSH открывается только для своего IP** (`My IP` в Security Group), а не для `0.0.0.0/0`.

!!! quote "Реальный кейс"
    Начинающий инженер закоммитил в публичный репозиторий файл с access key своего AWS-пользователя с правами администратора. Боты постоянно сканируют GitHub в поисках строк вида `AKIA...`, и через несколько минут ключ уже использовали: в нескольких регионах запустились десятки мощных инстансов для майнинга. Бюджета не было, и о проблеме он узнал из счёта на несколько тысяч долларов. AWS списал часть суммы как жест доброй воли, но ушла неделя переписки с поддержкой. Две минуты на бюджет и привычка проверять `git status` сэкономили бы эту неделю.

## Вопросы для самопроверки

<details markdown="1">
<summary>1. Почему нельзя работать в AWS под root user, если это удобнее всего?</summary>

У root нет ограничений: его права нельзя урезать политиками IAM. Любая ошибка (опечатка в команде удаления, утечка ключа) бьёт по всему аккаунту. Принцип **least privilege**: у каждого пользователя есть только те права, которые нужны для его задачи. Root нужен для редких операций вроде смены плана или закрытия аккаунта. Для работы используются IAM-пользователи (глава 04) и роли (глава 05).
</details>

<details markdown="1">
<summary>2. Бюджет на $10 настроен. Сервер на $50 в месяц работает уже неделю. Что сделает AWS?</summary>

Пришлёт письмо, когда расходы (или прогноз) превысят порог. Сам сервер **продолжит работать**. AWS Budgets не останавливает ресурсы, это только оповещение. Удалить ресурс должны вы. Бывают автоматические действия (*Budget actions*), но их нужно настраивать отдельно, и для обучения они избыточны.
</details>

<details markdown="1">
<summary>3. Вы создали EC2 в us-east-1, а консоль открыта в us-west-2. Где сервер?</summary>

В us-east-1, и он работает (а значит, тратит деньги), просто в этом регионе консоли его не видно. Большинство ресурсов AWS региональные. Если ресурс «пропал», первым делом проверьте регион. Найти все инстансы во всех регионах помогает **EC2 Global View** в консоли.
</details>

<details markdown="1">
<summary>4. Вы нашли свой access key в старом файле заметок. Достаточно удалить строку из файла?</summary>

Нет. Ключ продолжает работать, пока его не отозвали в AWS. Порядок такой:

1. IAM → Users → пользователь → **Security credentials** → ключ → **Deactivate**, затем **Delete**.
2. Проверить в **CloudTrail → Event history** (фильтр по access key), не пользовался ли ключом кто-то ещё.
3. Посмотреть **Billing** на неожиданные расходы.
4. Удалить строку из файла. Если файл был в git, ключ остался в истории, но отозванный ключ уже безопасен.
</details>
