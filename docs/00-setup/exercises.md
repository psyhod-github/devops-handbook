# 00 · Подготовка — задания

## Уровень 1 — повторение главы

1. Установите все инструменты из таблицы главы.
2. Настройте Git (`user.name`, `user.email`) и склонируйте свой fork пособия.
3. Зарегистрируйте аккаунт AWS, включите MFA для root.
4. Создайте бюджет $10 в месяц с оповещением на email.

!!! success "✅ Как проверить себя"
    Пройдите чек-лист из раздела [«Самопроверка» шпаргалки](commands.md#-самопроверка). Все пункты должны быть отмечены.

## Уровень 2 — мини-проект: свой репозиторий для заданий

Заведите на GitHub отдельный репозиторий `devops-homework`, куда будете складывать решения заданий второго уровня из всех глав. Сразу настройте его так, чтобы секреты туда не попали.

**Что сделать:**

1. Создайте репозиторий на GitHub (можно приватный) и склонируйте его.
2. Настройте доступ к GitHub по SSH-ключу вместо пароля.
3. Добавьте `.gitignore`, который исключает `*.pem`, `*.tfstate*`, `.terraform/`, `.env`, `terraform.tfvars`, `inventory.ini`.
4. Добавьте `README.md` со списком глав, которые будете заполнять.
5. Сделайте первый коммит и push.

<details markdown="1">
<summary>💡 Подсказки</summary>

- SSH-ключ: `ssh-keygen -t ed25519 -C "you@example.com"`. Публичную часть (`~/.ssh/id_ed25519.pub`) добавьте на GitHub → Settings → SSH and GPG keys. Проверка: `ssh -T git@github.com`.
- Клонировать по SSH: `git clone git@github.com:<you>/devops-homework.git`.
- Готовый `.gitignore` можно взять из корня этого пособия.
</details>

<details markdown="1">
<summary>✅ Критерии готовности</summary>

- [ ] `ssh -T git@github.com` отвечает `Hi <you>! You've successfully authenticated`.
- [ ] Создайте пустой файл `test.pem` и выполните `git status`: файла нет в списке неотслеживаемых. Затем удалите его.
- [ ] Коммит виден на GitHub.
</details>

## Уровень 3 — подумайте сами

<details markdown="1">
<summary>1. Вы на Free plan. Кредиты закончились через 3 месяца. Что произойдёт с аккаунтом и ресурсами в нём? Как избежать такой ситуации?</summary>

На Free plan аккаунт закрывается, когда кончаются кредиты или проходят 6 месяцев (что наступит раньше). Ресурсы в нём перестанут работать. Денег с карты не спишут, но и данные из закрытого аккаунта не вернуть, если не перейти на Paid plan за отведённый срок.

Как избежать:

- удалять ресурсы после каждой главы;
- раз в неделю смотреть **Billing → Free Tier** и **Credits**, сколько осталось;
- не создавать то, что стоит дорого даже в простое: NAT Gateway, балансировщики, кластеры EKS, RDS. Если глава требует такой ресурс, удалить его в тот же день.
</details>

<details markdown="1">
<summary>2. Почему MFA защищает root лучше, чем очень длинный пароль?</summary>

Длинный пароль защищает от подбора, но не от **кражи**: фишинговая страница, кейлоггер, утечка из менеджера паролей. MFA добавляет второй фактор, которым вы физически владеете (телефон или аппаратный ключ). Украденного пароля без него недостаточно. Это принцип защиты в глубину: одна сломанная защита не даёт полного доступа.
</details>

<details markdown="1">
<summary>3. Как узнать, в каких регионах у вас есть работающие ресурсы, если вы не помните, где что создавали?</summary>

- **EC2 Global View** (в консоли EC2) — инстансы, VPC, Security Groups во всех регионах на одном экране.
- **Billing → Bills** — расходы с разбивкой по сервисам и регионам.
- **Resource Explorer** — поиск по ресурсам всех регионов (нужно один раз включить).
- Из терминала (после главы 03): перебрать регионы в цикле.

  ```bash
  for r in $(aws ec2 describe-regions --query "Regions[].RegionName" --output text); do
    echo "$r: $(aws ec2 describe-instances --region $r --query 'Reservations[].Instances[].InstanceId' --output text)"
  done
  ```
</details>
